# 官网市场优先采购：本轮复核记录

更新：2026-09-27。范围是本开发分支的页面、keeper 和 `FlexiblePurchase` 购机入口；没有签名、广播、升级或测试主网资金。旧主网 Factory/Vault 尚未具备此分支的 Firsto 直购与机器登记能力，**不能直接把新页面产物指向旧部署**。

## 实际顺序

已募池的运营页面先按矿机系列与编号读取官网链上 `listingFor` 和矿机身份；官网原目标有合格挂单且价格在池上限内时，模拟 `buyFromMarket`，不请求 Firsto。只有官网原目标不合格时才核验 Firsto 原目标签名单。钱包确认前再次读取相同订单；官网挂单编号不变但价格或卖家变化也要求重新预览。

keeper 显式 `--venue auto` 先尝试官网原目标，再从官网独立快照发现同任务的替代矿机，逐笔读取有效挂单链上现价，补查快照后新增编号，核对验证权重与参考单位价，并执行完整 Vault 购机模拟。仅在官网扫描完成且当前挂单编号边界不变时考虑 Firsto 原目标签名单。官网数据超时、过旧、候选验证失败、模拟失败或新挂单出现都会暂停 Firsto 回退。CLI 的 `firsto-signed` 单渠道模式禁止发送新采购，只保留只读诊断和旧 journal 恢复。

合约层新增原目标官网优先保护：原目标 NFT 在官网有合格挂单时，任何人调用 `buyFromFirsto` 都回退。该检查在固定池和灵活池适用。费用、NFT 身份、模型、权重及余额约束仍由购机原子交易验证。

## 关键限制与待上线事项

链上无法经济地穷举官网所有**替代**矿机，因此权限外用户直接调用 Vault 时，合约只强制原目标的官网优先；替代矿机的跨市场顺序由 keeper 保证。Firsto 路径当前只购买原目标，不采购 Firsto 上的其他矿机。官网快照需来自站点公开源；虽然程序复查快照中的有效挂单和新编号，若官方源漏掉可重新激活的旧编号，仍不能将其视为全市场数学证明。挂单也可能在模拟后、打包前被抢先成交或改价，失败交易仍会消耗 Gas。

新源码与部署字节码、网页 ABI 摘要已同步生成，但它们不是现有主网部署的字节码。启用前需按现有治理流程完成 Vault/Factory 版本迁移、矿机登记回填、部署清单与链上实现代码核对，再单独验收真实小额购买。当前没有启动 `--send` keeper，也没有将新页面发布到旧主网测试链接。
